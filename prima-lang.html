The frame is the architecture

What does this
count as?

Prima is a constraint-first language. Every value is validated, transformed, and routed through three primitives — as, not_as, and fn[n]. No type system. No hidden state. Just frames.

Standalone C binary · ~1500 lines · no dependencies
Three primitives

The only three things you can say

Every prima program is built from exactly three statements. Nothing is hidden — no macros, no generics, no implicit coercion.
as

Positive constraint

x as number declares that x must count as a number. If it doesn't, the pipeline rejects it immediately. This is not a type — it's a decision about what you're willing to process.

not_as

Negative constraint

x not_as empty declares what x must absolutely avoid. Even if x passes the positive check, if it also matches the negative frame, the pipeline rejects it. This is how you say "that, but not that."

fn[n]

Categorical computation

fn[2] from math(a, b) selects the third function from a named space and applies it. The index is resolved at runtime — it can come from a binding. This is how computation is routed without conditionals.

-- frames define what values count as
email as alpha not_as empty;
score as number not_as negative;

-- spaces define available operations
space transform {
    fn[0] = double,
    fn[1] = abs,
    fn[2] = upper,
};

-- pipes chain constraints and computation
pipe process(raw, method) {
    raw as score;
    -> fn[method] from transform(raw);
    result as number;
    result not_as negative;
    output result;
};
How it works

Every pipeline is observable by construction

A pipeline executes linearly. Each step is one of three operations: check a constraint, apply a selected function, or emit a value. There is no branching, no recursion, no hidden control flow.
value → as frame → not_as frame → fn[n] from space → output
The trace is the execution. Every constraint check and every function application is visible in order. There is no optimizer, no JIT, no speculative execution — the pipeline is the program.
-- runtime: curve("Alice", 70, 0)
-- step 1: "Alice" as name → pass
-- step 2: 70 as score → pass
-- step 3: fn[0] from unary(70) → double → 140
-- step 4: 140 as number → pass
-- step 5: 140 not_as negative → pass
-- output: 140
Why prima

Frames, not types

Traditional type systems say what something is. Frames say what you count it as. The same value can be framed differently in different contexts — "42" is a number, but also even, nonzero, and a string representation. Each frame is a choice, not a property.

Get started

Build it in one command

Prima is a single C file. No dependencies, no package manager, no build system.
git clone https://github.com/your/prima.git && cd prima && cc -o prima prima.c -lm copy
./prima test.prima copy
Or start the REPL with no arguments to build pipelines interactively.
./prima - copy 
-- example.prima
name as alpha not_as number;
score as number not_as negative;

pipe check(x) {
    x as name;
    x not_as empty;
    output x;
};

check("Alice");
