Two primitives

as
position · connector · no value

The joint

Carries nothing. Pure topology. Tells the system whether a not_as adds or subtracts. The architecture is the arrangement of joints. Change the joint, change the question.

not_as
computation · function · returns a number

The substance

Does the work. Receives the input, returns a number. Never calls another not_as directly. Internals are free — externals are always just a value in an equation.

One rule

Every interconnection is + or −. No event bus, no dependency injection, no message queue. Every not_as receives the same input independently. The output is the arithmetic sum of all positioned values. Debugging is linear trace: expected sum vs actual sum, find the divergent term, fix it.

Three axioms

I

Synthesis with richness

Every decision holds thesis and antithesis. The unbiased synthesis is their average — because addition is commutative. Thesis first or antithesis first, T + A = A + T. The gap between them (richness) signals when to investigate, not merge.

II

Cross-domain simplification

True simplification widens, not narrows. A rendering bug is never just a rendering bug — simplify and the root cause lives in a different room. The last meal connects to the psychiatric symptom. The dot-connector is the path across domains.

III

Arithmetic architecture

A system has two kinds of thing: the joint (as) and the computation (not_as). Joints carry no value — they are pure position. Computations carry no position — they are pure value. All connections are + or −. No hidden state. No third kind.
